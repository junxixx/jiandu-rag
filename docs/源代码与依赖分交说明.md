# 源代码与依赖分交说明

本文档用于区分：**作品团队自研代码与资源**、**第三方依赖已安装副本**、**开发工具配置**，便于按赛方或归档要求打包；他人可结合根目录 `README.md` 与 `backend/.env.example` 复现运行环境（不包含 `node_modules` / `.venv` 本体）。

---

## 1. 团队自有「纯代码」主要范围（建议纳入源码包）

| 路径 | 说明 |
|------|------|
| `backend/app/` | Flask 应用、蓝图、服务、模型等 |
| `backend/scripts/` | 建库、种子数据、导入、运维脚本 |
| `backend/tests/` | 后端自动化测试 |
| `backend/wsgi.py` | 应用入口 |
| `frontend/src/` | Vue/TS 页面与组件等业务源码 |
| `frontend/public/` | 前端静态资源（图案、立绘 SVG、`models/chat/README.txt` 等） |
| `frontend/index.html` | 入口 HTML |
| `frontend/vite.config.ts` | Vite 构建配置 |
| `frontend/tsconfig*.json` | TypeScript 配置（若存在） |
| 根目录 `README.md` | 安装与运行说明（若赛方允许随源码附带） |

**说明**：`requirements.txt`、`package.json`、`package-lock.json` 属于**团队编写的依赖声明/锁文件**，不是第三方库的源代码；若要「可复现安装」，应一并保留（见第 3 节）。

---

## 2. 必须排除（不属于作品源代码 / 或不应外传）

| 路径或类型 | 原因 |
|------------|------|
| `.idea/` | IDE（如 JetBrains）工程与数据源配置，非业务代码 |
| `backend/.venv/` | Python 虚拟环境内已安装的第三方包 |
| `frontend/node_modules/` | npm 已安装的第三方包 |
| `backend/.env` | 含密钥、数据库密码等，**勿提交**；仅保留模板 `backend/.env.example` |
| `backend/.pytest_cache/` | pytest 本地缓存 |
| `frontend/dist/`（可选排除） | 构建产物，可由 `npm run build` 重新生成；若赛方要「仅手写源码」可不打包 |

**其他常见排除**：`chroma_data/`（向量库持久化）、大体量数据集目录（如 `DeepJiandu/`、`DeepJiandu_labels/`）可按赛方要求单独介质或网盘说明，不塞进「精简源码包」。

---

## 3. 建议与源码一并提交（非库源码，用于复现环境）

| 文件 | 作用 |
|------|------|
| `backend/requirements.txt` | 声明 Python 依赖及版本下限，供 `pip install -r` |
| `backend/.env.example` | 环境变量模板（无真实密钥） |
| `frontend/package.json` | 声明前端依赖与 npm 脚本 |
| `frontend/package-lock.json` | 锁定 npm 依赖版本，便于 `npm ci` 得到一致依赖树 |

## 7. 可安全删除清单（删后不影响仓库内的业务源代码）

下列项均为**生成物、缓存或第三方安装副本**，删除后 **`.py` / `.vue` / `.ts` 等自研文件不会少一行**；本地要能跑，只需按「恢复方式」重装或重建即可。

| 序号 | 路径或模式 | 是否建议删（交源码/瘦身磁盘） | 删除后对运行的影响 | 恢复方式 |
|:----:|------------|------------------------------|-------------------|----------|
| 1 | `.idea/` | 建议删（不交） | 无；仅失去当前 IDE 窗口/数据源等个人配置 | 用任意 IDE 重新打开项目即可 |
| 2 | `backend/.venv/` | 建议删（不交） | 暂时无法 `python` 运行后端，直到重装依赖 | `cd backend` → 建 venv → `pip install -r requirements.txt` |
| 3 | `frontend/node_modules/` | 建议删（不交） | 暂时无法 `npm run dev/build`，直到重装依赖 | `cd frontend` → `npm ci` 或 `npm install` |
| 4 | `frontend/dist/` | 可选删 | 无开发源码影响；少一份已构建的静态站 | `cd frontend` → `npm run build` |
| 5 | `backend/.pytest_cache/` | 可删 | 无 | 下次 `pytest` 自动重建 |
| 6 | `backend/**/__pycache__/` 与各层 `*.pyc` | 可删 | 无 | 运行 Python 时自动再生成 |
| 7 | `frontend/node_modules/.vite/`（随 3 一起删即可） | 可删 | 仅影响预构建缓存，非业务代码 | 随 `npm install` 再现 |

**与「源码无关」但删了会丢本地数据（需按 README 重建）**——若只关心「代码文件完整」，也可删；若还要本机一键跑通，请谨慎：

| 序号 | 路径 | 说明 |
|:----:|------|------|
| 8 | `chroma_data/` | 问牍向量库持久化目录；删后源码不变，需在管理端或接口 **重新建索引**（见 `README.md`） |
| 9 | `DeepJiandu/`、`DeepJiandu_labels/` | 数据集与标注；删后源码不变，简牍影像/导入功能需重新解压数据 |

**关于 `backend/.env`**：其中是密钥与本机配置，**不要打进对外压缩包**；从「交付物」角度应排除。若在你自己硬盘上**物理删除**该文件，业务源码仍完整，但需从 **`backend/.env.example`** 复制一份再填写才能启动后端（不属于上表「随便删无所谓」项，交包时**排除即可**，不必删自己工作副本）。

### 一键核对（PowerShell，在项目根目录执行）

仅打印常见可删目录是否存在，**不自动删除**：

```powershell
@('.idea','backend\.venv','frontend\node_modules','frontend\dist','backend\.pytest_cache','chroma_data') | ForEach-Object {
  if (Test-Path $_) { "存在: $_" } else { "无:   $_" }
}
```

实际删除前请自行确认无未备份的重要本地配置与数据。
